# M1-E iOS Pass Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give iOS the screenshot and recording protection Android already has, make the app submittable, and get it onto TestFlight — gated on proving KDF runs on an iPhone at all.

**Architecture:** iOS implements the **same** `setSecure` method on the **same** platform channel Android already implements, so no Dart changes are needed and every existing widget test keeps passing. Protection is two-layered: a secure `CALayer` that the system excludes from captures, plus `UIScreen.isCaptured` observation as a documented floor. The app-switcher cover lives in `SceneDelegate` and is always on.

**Tech Stack:** Flutter 3.41.4 (fvm-pinned), Swift / UIKit, XCTest, `komodo_defi_framework` (native Rust), Xcode on the owner's Mac, a physical iPhone.

**Spec:** `docs/superpowers/specs/2026-10-11-m1e-ios-pass-design.md`

## Global Constraints

- Build and test Flutter with `.fvm/flutter_sdk/bin/flutter`, never a bare `flutter` (the system one is Dart 3.7 and fails resolution). `flutter analyze` stays clean.
- **`lib/platform/secure_window.dart` must not change at all.** It already calls the channel correctly; if an edit there seems necessary, the seam was not reused properly — stop and say so.
- **`lib/widgets/secure_screen.dart` changes in exactly one way**, in Task 3: rendering the capture notice when `captureStateChanged` reports true. Nothing else in Dart changes, and the existing Dart tests must pass untouched.
- The platform channel is `me.digiscope.wallet/platform`. The method is `setSecure` with a boolean argument `secure`.
- Never log, print or render a seed word, a password or a `bio_pw_*` value — in Swift, Dart, tests, or device tooling. **Never run `uiautomator`-style dumps or screenshots on a seed screen**; on iOS, treat any successful capture of a seed as a leak to report.

## Review Focus

Input classes the spec implies that no happy path exercises. Each line's test belongs to the task named.

1. **A recording already running when the secure screen opens** — the secure layer only excludes captures; it does not blank an in-progress recording's view. Task 3 owns it.
2. **`setSecure(true)` called twice, or `false` without a preceding `true`** — the install/remove must be idempotent or the window's layer tree gets corrupted and the app renders blank. Task 2.
3. **Backgrounding *while* a secure screen is open** — the switcher cover and the secure layer both manipulate the window; they must compose rather than fight. Task 4.
4. **A second scene / iPad multitasking** — `UIApplication.shared.windows` assumptions break with more than one scene. Task 2 and Task 4 both touch this; Task 4 owns the test.
5. **The secure layer failing silently** — if a future iOS changes the behaviour, the app must log and fall back to the detection path, not pretend it is protected. Task 2.

```swift
// app/ios/Runner/SecureWindow.swift
import UIKit

/// Screenshot and screen-recording protection for the whole window.
///
/// iOS has no `FLAG_SECURE`. A `UITextField` in secure-entry mode owns a
/// layer the system excludes from screenshots and recordings; hosting the
/// window's layer inside it extends that exclusion to everything on screen.
///
/// **This behaviour is undocumented.** If a future iOS changes it, the
/// install fails, `didFallBack` goes true, and the caller must rely on the
/// capture-detection path instead (spec §4.3) rather than silently
/// believing the screen is protected.
final class SecureWindow {
  private let field = UITextField()
  private(set) var isInstalled = false
  private(set) var didFallBack = false

  func setSecure(_ secure: Bool, window: UIWindow?) {
    guard let window = window else { return }
    secure ? install(in: window) : remove(from: window)
  }

  private func install(in window: UIWindow) {
    guard !isInstalled else { return }          // Review Focus 2: idempotent
    field.isSecureTextEntry = true
    guard let secureLayer = field.layer.sublayers?.first else {
      didFallBack = true
      NSLog("[SecureWindow] secure layer unavailable; relying on capture detection")
      return
    }
    secureLayer.sublayers?.forEach { $0.removeFromSuperlayer() }
    window.layer.superlayer?.insertSublayer(secureLayer, at: 0)
    secureLayer.addSublayer(window.layer)
    isInstalled = true
    didFallBack = false
  }

  private func remove(from window: UIWindow) {
    guard isInstalled, let secureLayer = field.layer.sublayers?.first else {
      isInstalled = false
      return
    }
    window.layer.removeFromSuperlayer()
    secureLayer.superlayer?.insertSublayer(window.layer, at: 0)
    secureLayer.removeFromSuperlayer()
    isInstalled = false
  }
}
```

**The tests are the arbiter, not this snippet.** The layer manipulation is undocumented; if the exact calls differ on the SDK in use, adjust the implementation until the five tests pass and the device check in Task 7 shows a black recording — do not adjust the tests to match a broken implementation.

```swift
  private var onCaptureChange: ((Bool) -> Void)?

  var isCaptured: Bool { UIScreen.main.isCaptured }

  /// `UIScreen.capturedDidChangeNotification` is documented API, so this is
  /// the floor the product never falls below even if the layer trick breaks.
  func startObservingCapture(onChange: @escaping (Bool) -> Void) {
    onCaptureChange = onChange
    NotificationCenter.default.addObserver(
      forName: UIScreen.capturedDidChangeNotification, object: nil, queue: .main
    ) { [weak self] _ in
      guard let self = self else { return }
      self.handleCaptureChange(isCaptured: UIScreen.main.isCaptured)
    }
    onChange(UIScreen.main.isCaptured)   // report the state at subscribe time
  }

  /// Separated from the notification so tests can drive it.
  func handleCaptureChange(isCaptured: Bool) {
    onCaptureChange?(isCaptured)
  }
```

```swift

// app/ios/Runner/SceneDelegate.swift
import Flutter
import UIKit

/// Covers the window while the app is not active, so the snapshot iOS takes
/// for the app switcher never contains balances, addresses or a seed.
///
/// Applied on EVERY screen, not only secure ones (spec §5): an always-on
/// rule has no state to get wrong, and a balance in the switcher is a leak
/// too.
final class SceneCover {
  private var view: UIView?
  var isCovering: Bool { view != nil }

  func cover(_ window: UIWindow?) {
    guard let window = window, view == nil else { return }
    let shade = UIView(frame: window.bounds)
    shade.backgroundColor = .systemBackground
    shade.isOpaque = true
    shade.autoresizingMask = [.flexibleWidth, .flexibleHeight]
    window.addSubview(shade)
    view = shade
  }

  func uncover(_ window: UIWindow?) {
    view?.removeFromSuperview()
    view = nil
  }
}

class SceneDelegate: FlutterSceneDelegate {
  private let cover = SceneCover()

  override func sceneWillResignActive(_ scene: UIScene) {
    super.sceneWillResignActive(scene)
    cover.cover((scene as? UIWindowScene)?.keyWindow)
  }

  override func sceneDidBecomeActive(_ scene: UIScene) {
    super.sceneDidBecomeActive(scene)
    cover.uncover((scene as? UIWindowScene)?.keyWindow)
  }
}
```

Each scene gets its own `SceneDelegate`, hence its own `SceneCover` — that is what makes Review Focus 4 hold.
